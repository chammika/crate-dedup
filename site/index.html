crate-dedup

Crates whose outdated dependency makes the ecosystem compile two copies of the same crate, ranked by how much one upgrade would help. Expand a row for the reasoning.

How the score works
impact(L→D) = ∑R∈A(L,D) d90(R) k(R)
L
The crate to upgrade, using its latest version.
D
The outdated dependency. L requires an older semver line of D than its latest (^2 while syn 3 is out). A range that admits the latest version (>=0.52, <0.62 with 0.61.2 out) is not outdated.
A(L, D)
The affected crates: every crate R whose dependency tree contains L and also requires D's latest line, so R compiles D twice. R can be L itself. The Affected column is |A|.
d90(R)
Downloads of R (all versions) in the last 90 days, so current usage counts and abandoned crates count for little.
k(R)
The number of crates in R's tree that hold D on the same old line as L. All of them must upgrade before the duplicate disappears, so the credit is split k ways. The Sole column counts affected crates with k(R) = 1, where upgrading L alone removes the duplicate.

Scope: each crate's latest version and its normal, non-optional dependencies. Dev, build and optional dependencies are ignored, so real duplication is higher. Nested crates count more than once (if X depends on Y, both count), so impact ranks upgrades rather than counting builds.

Grace period: pairs whose new line of D was released less than 30 days ago are not ranked. Upgrade PRs that early are premature: lockstep projects often fix the duplicate in their next release, and new lines still get patches. This filters the list and doesn't change the score.

MSRV is not part of the score; it shows how hard the upgrade is. bump means D's latest version needs a newer Rust than L supports, so the PR also raises L's minimum supported Rust version, which some maintainers won't accept. ok means no raise is needed. ? means no MSRV is declared. When L declares none, it inherits the MSRV of its parent (the most downloaded crate from the same repository that depends on L, e.g. zerocopy-derive from zerocopy), shown as "via" in the row details.
